Discovery Requirement

3 things that I did not know:

1) There are fundamental differences in how hotkeys are called from Mac and from Linux, despite the fact that they are both Unix. I ran into several failing tests early on because the tests relied on hard-coded calls to Mac's hotkey Meta+, rather than the Control key that my WSL Ubuntu distro was using. Once I realized that, it was easy for me to get to 0 failures. I found this issue in the e2e test suite. It matters because although most engineers work on Mac, the actual repo would fail testing in the environment (Linux) where it is to be deployed. In the future, I can apply this change to testing by ensuring that i don't hardcode this hotkey and instead check the OS where the code is running and set the hotkey based on that.

2) Although the agent CAN drastically reduce the work needed to assign types correctly in replacing the any types, it needs a ton of hand-holding to do so. I had never attempted to use an agent for this purpose. I would not have thought that the agent would struggle with types as it did when I tried to tell it to "just do it," but because of my own experience and skill writing types in Typescript in the past, I was able to point out to the agent what good typing would look like, what complex types we should be using in which situations, and then guide it through the larger implementation. In the future, I think that I would try setting up more specific scaffolding that explained why certain types would need certain parameters, and then from there attempt to "one shot" the implementation.

3) There are still bugs that are obvious to humans that are seemingly impossible for the agent to pick up on. Notably, the title syncing issue seemed never to enter the agent's attention space, even though a user would encounter the issue almost immediately when using the app for its intended purpose. It was necessary for me to identify this syncing issue (title would not sync for users until they reloaded the page) and then point out where in the code this may be happening, in order for the agent to see what was causing it in the code and make the correction. I found this bug very late in my process. Although that is not an issue and of itself, I could have found the bug earlier if I had done more hands-on testing earlier.
