Architecture

Standalone agent process. HTTP + WebSocket. Never shares DB connections.

Ship API (:3000)

  • Express + PostgreSQL
  • REST endpoints for issues, projects, documents
  • WebSocket /events — broadcasts on every mutation
  • Bearer token auth for service account

FleetGraph Agent (:3001)

  • LangGraph StateGraph (single graph, all 8 use cases)
  • EventListener: WebSocket + 30s debounce
  • Scheduler: briefing (daily) + staleness (hourly)
  • SSE endpoint for on-demand chat

Key Conditional Edges

  • After User Context: which fetch nodes to fan-out
  • After Fetch: thresholds (proactive) or straight to Gemini (on-demand)
  • After Gemini: suggestions (violations) or notify only (clean)

Architecture Decisions

7 key decisions documented in FLEETGRAPH.md. Each with tradeoffs considered.

1. LangGraph

Conditional branching, parallel fan-out, native LangSmith tracing. Raw functions would require manual orchestration. CrewAI/Autogen are for multi-agent, not single-agent state graphs.

2. Gemini 2.5 Flash

Fast inference (1-10s), streaming SSE support, 1M context window, very low cost. Single model simplifies deployment — no model routing needed.

3. Threshold + Gemini Split

Thresholds are deterministic math (zero cost, instant, unit-testable). Gemini only runs after — prompt mode determined by threshold results. If Gemini is down, violations still surface.

4. Ephemeral State + Persistent Actions

Graph runs are stateless and idempotent. agent_actions table is the only persistence. Crashed run = no side effects beyond what was already written.

5. Actions as Table, Not Documents

Ship's "everything is a document" model is for user content. Suggestions are ephemeral workflow artifacts with lifecycle state + severity scores. Dedicated table with indexes serves the action queue UI.

6. Hybrid Trigger Model

Event-driven (WebSocket) for mutations: sub-minute detection. Scheduled (cron) for time-based: staleness can't fire a webhook. Pure polling is wasteful; pure webhooks miss absence-of-events.

7. Chat Embedded in Context

Slide-out overlay, not a standalone page. Opening on a project scopes Gemini to that project's data. "What are the biggest risks?" means different things on different pages. Ephemeral — closing discards conversation.

Why It's Easy

  • Event-driven scoping: only affected project + person fetched
  • Threshold evaluator: pure math, zero cost, instant
  • Debounce coalesces: 50 changes in 10s = 1 graph run
  • Scales with write volume, not project count

Worst Case

30s debounce + 3s fetch + 15s Gemini + 2s persist = ~50 seconds

Even 2x worst case = 100s. Still well under 5 minutes.

Key Nodes to Point Out
